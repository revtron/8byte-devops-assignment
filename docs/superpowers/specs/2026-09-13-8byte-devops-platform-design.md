# 8byte DevOps Assignment — Platform Design

**Date:** 2026-09-13
**Status:** Approved for planning
**Source:** `8byte_-_DevOps_assignment.pdf` (Parts 1–4 + deliverables)

## 1. Goal

Deliver an end-to-end, reproducible DevOps platform on AWS for a small todo
application, covering the four parts of the assignment:

1. Infrastructure provisioning with Terraform
2. CI/CD with Jenkins (tests, scans, image push, staging deploy, manual prod gate, failure notifications)
3. Monitoring and centralized logging with Prometheus / Grafana / Loki
4. Documentation, secret management, and backups

Happy path first. Good practices and "what extra code would help" are noted in
the README rather than built where they would blow the time budget.

## 2. Decisions (with reasons)

| Area | Decision | Why |
|---|---|---|
| Cloud / region | AWS, `ap-south-1` | Assignment prefers AWS; Mumbai is closest to the reviewer |
| Compute | EC2 + Docker (Amazon Linux 2023) | User choice; gives a real OS to show infra metrics and bastion access |
| Topology | 3 EC2: **management** (bastion + Jenkins, public), **backend** (app, private), **mon** (monitoring, private) | Strict jump-host model; Jenkins on management saves a box |
| Application | Node 20 + Express, vanilla HTML/CSS/JS frontend, PostgreSQL | One language; trivial to instrument and test |
| Environments | Single infra; `prod` and `staging` are two containers on the backend box with separate ALB listeners and separate databases | Near-zero extra cost with real process/data/URL separation; Terraform is parameterized so physical separation is a tfvars change |
| Registry | Docker Hub, public repo | User choice; no pull credentials needed on the box |
| CI/CD | Jenkins LTS on management, configured by JCasC, multibranch pipeline, `Jenkinsfile` | User choice; stronger ownership story than a hosted runner |
| Deploys | Jenkins → `aws ssm send-command` → `deploy.sh` on backend | No SSH keys stored in Jenkins; IAM-authorized and auditable |
| Human access | SSH only, via management (ProxyJump); UIs via SSH tunnels | User requirement: no direct access to backend/mon |
| Monitoring | Prometheus + Grafana + Loki + Alertmanager on mon | User choice |
| Notifications | SNS → email (pipeline failures and Prometheus alerts) | User choice; no Slack workspace |
| Egress | Single NAT gateway | Textbook; per-AZ NAT noted as HA improvement |
| State | S3 (versioned, encrypted) + DynamoDB lock, created by a bootstrap root | Standard remote state |
| Secrets | AWS Secrets Manager | DB password generated by Terraform; Docker Hub token, GitHub PAT, Jenkins admin password written by a helper script so values never enter state |
| Backups | RDS automated backups, 7-day retention, plus documented manual snapshot procedure | Nearly free; satisfies Part 4.2 alongside secrets |

## 4. Infrastructure (Part 1)

### 4.1 Network
- VPC `10.0.0.0/16`, two AZs (`ap-south-1a`, `ap-south-1b`).
- Public subnets `10.0.0.0/24`, `10.0.1.0/24` (ALB, management). Private subnets
  `10.0.10.0/24`, `10.0.11.0/24` (backend, mon, RDS).
- Internet gateway; one NAT gateway in `ap-south-1a`; private route tables → NAT.
- VPC flow logs not enabled (noted as improvement).

### 4.2 Hosts

| Host | Subnet | Type | Public IP | Runs |
|---|---|---|---|---|
| management | public a | t3.small | Elastic IP | sshd (bastion), Jenkins LTS, Docker, Trivy, AWS CLI, git |
| backend | private a | t3.micro | none | Docker (todo-prod :3000, todo-staging :3001), node_exporter :9100, promtail |
| mon | private a | t3.small | none | docker-compose: prometheus :9090, grafana :3000, loki :3100, alertmanager :9093, postgres_exporter :9187, node_exporter :9100 |

All hosts: Amazon Linux 2023, IMDSv2 required, root volume gp3 encrypted, SSM
agent (preinstalled) enabled, `ec2-user` login disabled once the named user
exists.

### 4.3 Users and SSH (user requirement)
- Terraform variable `admin_public_key` (string) and `admin_cidr` (your IP/32).
- cloud-init on each host creates one Linux user — `management`, `backend`,
  `mon` respectively — with the public key, passwordless sudo, and sshd
  hardened: `PasswordAuthentication no`, `PermitRootLogin no`,
  `AllowUsers <that user>`.
- `terraform output -raw ssh_config` renders:
  ```
  Host management
    HostName <eip>            User management   IdentityFile ~/.ssh/8byte
    LocalForward 8080 localhost:8080    # Jenkins UI
  Host backend
    HostName <backend-ip>     User backend      ProxyJump management
  Host mon
    HostName <mon-ip>         User mon          ProxyJump management
    LocalForward 3000 localhost:3000    # Grafana
    LocalForward 9090 localhost:9090    # Prometheus
  ```
- `scripts/setup-ssh.ps1` / `setup-ssh.sh` append that block to `~/.ssh/config`
  and add shell aliases so that typing `management`, `backend`, or `mon` runs
  `ssh <alias>`.

### 4.4 Security groups (the only allowed paths)

| SG | Inbound from | Ports |
|---|---|---|
| alb | 0.0.0.0/0 | 80 (prod), 8080 (staging) |
| management | `admin_cidr` | 22 |
| backend | alb | 3000, 3001 |
| backend | management | 22 |
| backend | mon | 9100, 3000, 3001 (scrapes) |
| mon | management | 22 |
| mon | backend | 3100 (Loki push) |
| rds | backend, mon | 5432 |

Egress: all hosts allow all outbound (via NAT for private). No other inbound.

### 4.5 Load balancer
- Application Load Balancer in public subnets.
- Target groups `todo-prod` (backend:3000) and `todo-staging` (backend:3001),
  health check `GET /health`, healthy threshold 2, interval 15 s.
- Listeners: `:80 → todo-prod`, `:8080 → todo-staging`. HTTP only (no domain);
  HTTPS via ACM noted as improvement.
- Access logs to an S3 bucket with 30-day lifecycle expiry.

### 4.6 Database
- RDS PostgreSQL 16, `db.t4g.micro`, 20 GB gp3, single-AZ, private subnet
  group, `publicly_accessible = false`, storage encrypted.
- Master password: `random_password` → Secrets Manager secret `todo/db`
  (JSON: host, port, username, password, dbname_prod, dbname_staging).
- Two logical databases `todo_prod` and `todo_staging`, created by the backend
  host's first-boot script (`CREATE DATABASE IF NOT EXISTS` equivalent via
  `psql`).
- Backups: automated, `backup_retention_period = 7`, window 20:00–21:00 UTC,
  `skip_final_snapshot = true` and `deletion_protection = false` because this
  is a disposable demo (both called out in README with prod values).
- Performance Insights off (cost). CloudWatch RDS metrics remain available.

### 4.7 IAM
- **management role:** `AmazonSSMManagedInstanceCore`; `ssm:SendCommand` on
  the backend instance and `AWS-RunShellScript` document; `ssm:GetCommandInvocation`;
  `sns:Publish` on the alerts topic; `secretsmanager:GetSecretValue` on
  `todo/jenkins/*` secrets.
- **backend role:** `AmazonSSMManagedInstanceCore`; `secretsmanager:GetSecretValue`
  on `todo/db`.
- **mon role:** `AmazonSSMManagedInstanceCore`; `secretsmanager:GetSecretValue`
  on `todo/db` (for postgres_exporter); `sns:Publish` on the alerts topic
  (Alertmanager SNS receiver).
- Human AWS keys are used only locally for Terraform; they are never stored on
  any instance or in Jenkins.

### 4.8 State management
- `terraform/bootstrap`: S3 bucket `8byte-tfstate-<account-id>` (versioning,
  SSE-S3, public access blocked) and DynamoDB table `8byte-tflock`. Local
  state, applied once.
- Main root `backend.tf` uses that bucket with key `dev/terraform.tfstate`.

### 4.9 Variables and outputs
- `variables.tf`: `project`, `env`, `region`, `vpc_cidr`, `azs`,
  `instance_types` (map), `db_instance_class`, `db_allocated_storage`,
  `admin_cidr`, `admin_public_key`, `alert_email`, `dockerhub_repo`,
  `github_repo`, `tags`.
- `outputs.tf`: `alb_dns_name`, `prod_url`, `staging_url`, `management_eip`,
  `backend_private_ip`, `mon_private_ip`, `rds_endpoint`, `db_secret_arn`,
  `sns_topic_arn`, `ssh_config` (rendered template), `state_bucket`.

## 5. Application

- **Express** app on port from `PORT` env. Serves `public/` statically and:
  - `GET /api/todos`, `POST /api/todos {title}`, `PATCH /api/todos/:id {title?, done?}`, `DELETE /api/todos/:id`
  - `GET /health` → `{status, env, version, db: "ok"|"error"}` (503 on DB error)
  - `GET /metrics` → Prometheus text (`prom-client`): default Node metrics,
    `http_requests_total{method,route,status,env}`,
    `http_request_duration_seconds` histogram.
- **Config via env:** `PORT`, `APP_ENV` (`prod`|`staging`), `DATABASE_URL`,
  `APP_VERSION` (image tag, injected by deploy.sh).
- **Logging:** `pino` + `pino-http` JSON to stdout; access log lines include
  `env`, `method`, `url`, `status`, `responseTime`, `reqId`.
- **Schema:** `CREATE TABLE IF NOT EXISTS todos (id serial pk, title text not null, done bool default false, created_at timestamptz default now())` run at startup.
- **Frontend:** single page — list, add, toggle done, delete; fetches
  `/api/todos`; shows `env` + `version` badge from `/health`.
- **Tests:**
  - Unit (Jest): title validation, route handlers with a mocked repository.
  - Integration (Jest + supertest): full CRUD against Postgres at
    `DATABASE_URL`; skipped with a clear message if the variable is unset.
- **Dockerfile:** multi-stage (`npm ci --omit=dev`), runs as `node` user,
  `HEALTHCHECK` on `/health`, `EXPOSE 3000`.

## 6. CI/CD (Part 2) — Jenkins

### 6.1 Jenkins installation (management host, cloud-init)
- Install Java 17, Jenkins LTS (official RPM repo), Docker (jenkins user in
  `docker` group), Trivy, AWS CLI v2, git, Node 20 (for fast lint/test without
  containers).
- `plugins.txt` installed via `jenkins-plugin-cli`: configuration-as-code,
  workflow-aggregator, git, github-branch-source, credentials, credentials-binding,
  junit, htmlpublisher, timestamper, ansicolor.
- `/etc/systemd/system/jenkins.service.d/override.conf` sets
  `CASC_JENKINS_CONFIG=/var/lib/jenkins/casc/jenkins.yaml` and exports
  `JENKINS_ADMIN_PASSWORD`, `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`,
  `GITHUB_TOKEN`, `GITHUB_REPO`, `BACKEND_INSTANCE_ID`, `SNS_TOPIC_ARN`,
  `ALB_DNS`, `AWS_REGION` — values fetched from Secrets Manager / instance
  metadata by a boot script, so nothing is hard-coded in the YAML.
- Setup wizard disabled; JCasC defines the `admin` user, the three
  credentials, and a **Multibranch Pipeline** job `todo` pointing at the GitHub
  repo (GitHub Branch Source plugin, authenticated with the PAT), discovering
  branches and PRs, periodic scan every **1 minute** so every push starts a
  build within 60 s. Build results are posted back to GitHub as commit
  statuses (green tick / red cross on commits and PRs). Inbound webhooks are
  deliberately not used so Jenkins stays fully private; noted as the upgrade
  path.

### 6.2 `Jenkinsfile` stages

| # | Stage | Runs on | Details |
|---|---|---|---|
| 1 | Checkout | all | git checkout, compute `GIT_SHA` short tag |
| 2 | Install & Lint | all | `npm ci`, `npm run lint` |
| 3 | Unit tests | all | `npm run test:unit`, JUnit report |
| 4 | Integration tests | all | `docker run postgres:16` sidecar, `npm run test:integration`, JUnit report |
| 5 | Dependency scan | all | `npm audit --audit-level=high` (non-blocking warn) + `trivy fs --severity HIGH,CRITICAL --exit-code 1 app/` |
| 6 | Terraform check | PRs touching `terraform/` | `terraform fmt -check -recursive`, `terraform validate` (in Docker `hashicorp/terraform`) |
| 7 | Build image | `main` | `docker build -t $REPO:$GIT_SHA -t $REPO:latest app/` |
| 8 | Image scan | `main` | `trivy image --severity CRITICAL --exit-code 1 $REPO:$GIT_SHA`; HTML report archived |
| 9 | Push image | `main` | docker login with Docker Hub credentials, push both tags |
| 10 | Deploy staging | `main` | `aws ssm send-command --instance-ids $BACKEND --document-name AWS-RunShellScript --parameters 'commands=["/opt/todo/deploy.sh staging <sha>"]'`, wait for completion |
| 11 | Smoke test staging | `main` | `scripts/smoke-test.sh http://$ALB_DNS:8080` |
| 12 | Approve production | `main` | `input message: "Promote <sha> to production?"`, `timeout(30, MINUTES)` |
| 13 | Deploy production | `main` | same SSM call with `prod` |
| 14 | Smoke test production | `main` | `scripts/smoke-test.sh http://$ALB_DNS` |

`post { failure { aws sns publish ... } }` sends job name, branch, build URL,
and the failed stage. `post { always }` archives JUnit and Trivy reports.
Images are never rebuilt between staging and prod — the same digest is
promoted.

### 6.3 `deploy.sh` (on backend, invoked via SSM)
```
deploy.sh <env: prod|staging> <tag>
```
1. Read `todo/db` from Secrets Manager → build `DATABASE_URL` for the env.
2. `docker pull $REPO:$tag`.
3. `docker rm -f todo-$env` (if exists); `docker run -d --name todo-$env
   --restart unless-stopped -p <3000|3001>:3000 -e APP_ENV -e DATABASE_URL
   -e APP_VERSION=$tag --log-driver json-file --label env=$env $REPO:$tag`.
4. Poll `localhost:<port>/health` up to 60 s; exit non-zero on failure (which
   fails the Jenkins stage). Previous image is left for manual rollback
   (`deploy.sh prod <previous-tag>`).

Brief downtime (~2–5 s) per deploy is accepted for the happy path; blue/green
via a second target group is noted as improvement.

## 7. Monitoring and logging (Part 3)

### 7.1 Metrics (Prometheus on mon, 15 s scrape, 15-day retention)
- `node_exporter` on backend and mon → CPU, memory, disk, network.
- App `/metrics` on backend:3000 (prod) and :3001 (staging) → request rate,
  error rate, latency histograms, Node runtime.
- `postgres_exporter` on mon connected to RDS (credentials from `todo/db`) →
  connections, transactions/s, cache hit ratio, deadlocks, DB size.
- Prometheus itself, Loki, Grafana self-metrics.

### 7.2 Logs (Loki on mon, filesystem storage, 7-day retention)
- promtail on backend ships:
  - Application + access logs: Docker json-file logs under
    `/var/lib/docker/containers/*/*.log`, labelled with `container`, `env`
    (via Docker service discovery + relabel on container label).
  - System logs: `/var/log/messages`, `/var/log/secure`, `/var/log/cloud-init-output.log`.
- promtail on mon ships its own system logs and the monitoring containers' logs.
- ALB access logs go to S3 (not into Loki) — noted in README.

### 7.3 Dashboards (provisioned from JSON, no click-ops)
1. **Todo — Application:** request rate, error rate (%), p50/p95/p99 latency,
   requests by route/status, per-env selector, live log panel from Loki.
2. **Infrastructure:** per-host CPU, memory, disk usage and I/O, network,
   load average, uptime.
3. **PostgreSQL:** connections vs max, TPS, cache hit ratio, rows
   fetched/inserted, DB size, deadlocks.

### 7.4 Alerts (Prometheus rules → Alertmanager → SNS email)
- `InstanceDown` (up == 0 for 2 m), `HighErrorRate` (5xx > 5 % for 5 m),
  `HighLatency` (p95 > 1 s for 5 m), `DiskAlmostFull` (> 80 %),
  `HighMemory` (> 90 %), `PostgresDown`, `PostgresTooManyConnections` (> 80 % of max).
- Alertmanager `sns_configs` publishes to the same topic as the pipeline;
  the mon instance role grants `sns:Publish`.

## 8. Documentation and best practices (Part 4)

- **README.md:** prerequisites, bootstrap → apply → put-secrets → setup-ssh
  → first Jenkins run walkthrough; architecture diagram (Mermaid) and
  decisions; security considerations; cost table and optimizations; backup
  and secrets sections; "good practices I'd add next" list.
- **docs/APPROACH.md:** how the work was sequenced and why.
- **docs/CHALLENGES.md:** kept as a running log during implementation.
- **Secret management:** Secrets Manager for DB creds (generated), Docker Hub
  token, GitHub PAT, Jenkins admin password; fetched at boot by instance
  roles; never in Terraform state (except the generated DB password, which is
  in encrypted, versioned, access-controlled S3 — stated explicitly).
- **Backup strategy:** RDS automated backups (7 days), manual snapshot
  procedure, Terraform state versioning in S3, Jenkins config recoverable from
  JCasC.

## 9. Local developer loop
- `docker compose up` in `app/` starts Postgres + app on `localhost:3000`.
- `npm test` runs unit tests; `DATABASE_URL=... npm run test:integration`
  runs integration tests.
- `docker compose up` in `monitoring/` can be run locally against the same
  app for dashboard development (Prometheus targets overridden via env).

## 10. Execution order
1. App + tests + Dockerfile (runs locally, green tests).
2. Terraform bootstrap + main root; `plan` reviewed with the user; `apply`
   only on explicit go.
3. Monitoring stack config; verify on mon.
4. Jenkins JCasC + Jenkinsfile; first pipeline run end-to-end.
5. SSH aliases, README, APPROACH, CHALLENGES.
6. Push to GitHub, final `destroy` decision left to the user.

## 11. Out of scope (documented as improvements)
HTTPS/ACM + domain, multi-AZ RDS, per-AZ NAT, autoscaling group, blue/green
deploys, VPC flow logs, GitHub webhooks into Jenkins, OIDC-federated CI
credentials, Loki S3 storage, Grafana SSO, WAF.

## 12. Cost estimate (while everything is up, ap-south-1)
NAT ≈ $0.05/h, ALB ≈ $0.025/h, RDS t4g.micro ≈ $0.02/h, 2× t3.small + 1×
t3.micro ≈ $0.06/h, EIP/EBS/S3 ≈ $0.01/h → **≈ $0.17/h, ≈ $4/day**. Destroy
when not in use; a 3-day working window costs well under $15.

## 13. Post-implementation deviations (recorded 2026-09-13)

The code on `main` is the source of truth; these are the places where it
intentionally differs from the sections above and why.

| Spec says | Code does | Why |
|---|---|---|
| Secrets `todo/db`, `todo/jenkins/*`; TGs `todo-prod/staging` | `8byte/db`, `8byte/dockerhub`, `8byte/github`, `8byte/jenkins`; TGs `8byte-prod/staging` | One `8byte-` prefix for every resource (cross-track contract) |
| Jenkins admin password written by `put-secrets.sh` | Generated by Terraform (`random_password`) into `8byte/jenkins`; Grafana reuses it | Removes a boot-order dependency; one less manual secret |
| RDS identifier `8byte-db` | `db-8byte`, parameter group `pg16-8byte` | RDS identifiers must start with a letter |
| System logs from `/var/log/messages`, `/var/log/secure` | promtail `journal` scrape + cloud-init/bootstrap log files | Amazon Linux 2023 is journald-only |
| IAM: backend reads only `8byte/db`; mon reads `8byte/db` | backend + mon also read `8byte/github`; mon reads `8byte/jenkins` | user-data needs the optional GitHub token to clone; mon needs the Grafana password |
| `.terraform.lock.hcl` ignored | Committed, provider pinned `~> 5.100` | Reproducible applies |
| Alerts: 7 rules | 9 rules (+ `HighCpu`, `PostgresDeadlocks`) | Cheap, useful |
| `ssh_config` inline comments | Comments on their own lines | OpenSSH < 8.5 rejects trailing comments |
| IMDSv2 `http_tokens = required` | + `http_put_response_hop_limit = 2` | Containers (Alertmanager, exporters, Jenkins jobs) need instance-role credentials through the Docker bridge |
| `DATABASE_URL` plain | `?sslmode=require`; image bundles the RDS CA via `NODE_EXTRA_CA_CERTS` | RDS PostgreSQL 16 forces SSL; node-postgres verifies the chain |
